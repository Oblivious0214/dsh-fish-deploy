# DSH 养鱼部署包

**给 DSH 的部署说明直链：** https://raw.githubusercontent.com/Oblivious0214/dsh-fish-deploy/main/README.md

**机器可读安装清单：** https://raw.githubusercontent.com/Oblivious0214/dsh-fish-deploy/main/deploy.json

## 给人类看

**DSH 版本是强制条件：本套插件要求先更新至 `0.2.1-rc.3`，或通过插件兼容检查的更高版本。版本不满足时必须先更新；选择不更新，就结束整套安装流程。**

**安装有兼容条件：QQ 聊天界面可能与其他 UI 美化插件冲突，强烈建议先关闭其他 UI 美化插件，再安装或启用 QQ 聊天界面。** 其他皮肤、主题美化、气泡或聊天布局插件可能覆盖同一界面；独立分段插件也应停用。安装完成并确认界面正常后，再按需逐个恢复其他插件。

通过几个插件组合，让 DSH 获得类似 QQ 的聊天界面，并支持角色扮演。兼容表情包和 AI 语音 TTS 插件，不用准备 QQ 小号，也省去养鱼小号被封的顾虑。

**把上面的部署说明直链发给 DSH，让它帮你部署即可。** 直链只返回文档正文，避免 GitHub 导航页面影响读取。

自动下载始终失败时，DSH 会暂停安装并给出所需 TGZ 的下载链接。用浏览器下载后，把 TGZ 文件拖进当前 DSH 对话即可交给它继续处理，无需解压。

项目链接：https://github.com/Oblivious0214/dsh-fish-deploy

## 给 DSH 看

当用户将本项目链接交给你进行部署时，必须先通过下述版本检查，再完成基础安装，引导用户设置聊天外观和人格，最后按需添加表情包、语音功能。

### 第一步：强制检查 DSH 版本

**本套部署要求 DSH `0.2.1-rc.3` 起。`0.2.1-rc.2` 及更旧版本必须先更新，不能继续安装。** 当前验证环境为 `0.2.1-rc.3-22ddee3`；同一 rc.3 的源码构建后缀不要求完全相同。更高版本仍须通过插件自身的兼容检查，不能仅凭版本更高就绕过检查。

1. 先使用当前上下文、DSH「关于」页或当前安装的版本信息，确认实际运行的 DSH 版本。不要为查版本扫描整个磁盘或用户目录，也不要用其他安装目录的版本代替当前实例。
2. 低于上述版本时，明确提示：「本套插件要求 DSH 0.2.1-rc.3 或兼容的更高版本，请先更新 DSH；不更新则结束安装。」用户选择不更新、暂缓或更新失败时，立即结束整套部署，不能先装人设、表情包或语音来继续本套流程。
3. 用户同意更新时，按 DSH 官方更新入口及实际安装通道处理；更新完成、重新启动 DSH 并复核运行版本后，才可继续。仅下载更新或口头同意更新不算检查通过。
4. 无法确认版本时，停止安装，说明需要确认当前版本。版本检查通过前，不下载或安装插件，也不修改依赖、停用插件或改写配置。

`deploy.json` 同步记录最低版本和必须停止的分支，供部署代理执行；它是部署清单，不会自行运行版本检查。每条安装路径都必须遵守此检查，宿主的兼容性拒绝与回滚仍保留。

### 安装前先检查兼容性

**安装有兼容条件：QQ 聊天界面可能与其他 UI 美化插件冲突，强烈建议先关闭其他 UI 美化插件，再安装或启用 QQ 聊天界面。** 其他皮肤、主题美化、气泡或聊天布局插件可能覆盖同一界面；独立分段插件也应停用。安装完成并确认界面正常后，再按需逐个恢复其他插件。

使用下方插件清单检查结果，先识别已启用的其他 UI 美化插件，向用户说明可能冲突的项目，建议先停用并保留配置；根据用户的部署授权处理，未授权停用时请用户先手动关闭。保留人设、Fish TTS、表情包等功能插件，不把“关闭其他插件”理解为停用所有插件。插件类型无法判断时说明情况，不直接批量停用。

### 先走这条安装路径

本页已经给出全部安装目标。直接按下列顺序操作，无需浏览两个插件的仓库、克隆源码或自行编写安装程序。

1. 确认已通过上面的强制版本检查，再检查当前会话工具表中是否实际存在 `plugin_manager`。存在时先调用 `{"action":"list_bundles","limit":100}`，根据结果检查是否已安装，并完成上面的 UI 插件冲突检查；有 `nextOffset` 时继续翻页。该工具已经绑定当前 profile，无需先寻找 profile 路径或安装入口。
2. 工具不存在时，直接使用下方备用入口，不尝试调用不存在的工具，也不为了安装插件先改动工具启用配置。profile 里只列出 base/web 等 bundle，不能据此判断工具是否可用，以实际工具表为准。
3. 完成兼容检查后，对尚未安装或需要升级的目标，分别调用下面的两个安装请求。通常直接使用 TGZ 链接；下载超时按下方代理排查和本地包备用流程处理，无需解压或重打包。
4. 根据结果中的状态和 `nextStep` 处理启用、重启或错误，再继续本页的配置引导。权限被拒绝时停下，按正常权限流程处理。

```json
{"action":"install_bundle","target":"https://github.com/Oblivious0214/dsh-toy-persona/releases/download/v0.3.1-toy.14/dsh-persona-switcher-0.3.1-toy.14.tgz","enabled":true}
```

QQ 聊天界面：

```json

```

**工具不可用时使用备用入口：** 检查当前环境是否已有 `dsh` 命令，并确认实际 profile；使用 `dsh plugin --profile <实际 profile> add "<上面的 TGZ 链接>"`。Desktop 的命令可能不在 PATH；此时根据当前 Desktop 的实际安装位置，定位其 `resources\runtime\cli\bin\dsh.cmd`，用绝对路径调用。不要重新安装 DSH，也不要默认猜测安装目录或 profile 是 `desktop`、`web`。该 CLI 会处理依赖安装、bundle 注册和兼容性检查，不要自行手改清单代替安装。CLI 不可用时，引导用户在 DSH「插件」页通过 TGZ 链接安装。

**读取文档失败时：** GitHub 页面只返回导航，就直接读取顶部的原始文档直链，不再反复抓取仓库页面。

### 下载超时与 VPN / 代理排查

`ETIMEDOUT`、`UND_ERR_CONNECT_TIMEOUT` 或 `fetch failed` 可能与直连不稳定、代理未生效或分流有关，不能仅凭错误认定插件包损坏或 Node 有缺陷。PowerShell 偶尔成功，也不能证明 pnpm 使用了相同的代理路径。

1. 区分请求来源：Release TGZ 由 pnpm/Node 下载，不经过 Git；`github:` 源码安装还会调用 Git。Git 未安装时先处理缺失问题；Git 的 `http.proxy` 不会自动配置 pnpm 的 TGZ 下载。
2. 使用 VPN / 代理软件时，检查 DSH、pnpm/Node 的请求是否确实进入代理，以及 GitHub 和附件重定向域名（例如 `release-assets.githubusercontent.com`）的实际分流结果。客户端「全局」规则与 TUN 接管是不同设置，不能只看开关名称；以连接日志和实际路由为准。没有代理环境变量，也不代表 TUN 等接管一定未生效。
3. 检查当前 DSH 安装进程实际继承的 `HTTP_PROXY`、`HTTPS_PROXY`、`NO_PROXY`，以及 pnpm 的 HTTPS 代理配置；显示诊断时隐藏代理凭据。仅设置 Windows 系统代理，不应视为 pnpm/Node 已配置完成。代理端口以用户现有软件为准，不猜测端口，不擅自改系统或全局 Git/pnpm 设置。已运行的 Desktop 不会因外部终端设置变量就自动获得这些变量。
4. 单独用 Node 24 的原生 `fetch()` 诊断时，环境代理支持需通过 `NODE_USE_ENV_PROXY=1` 或受支持的 `--use-env-proxy` 启用；pnpm 仍需按其自身代理配置核对。记录失败 URL、错误码、是否经过代理，以及有超时限制的 HEAD/实际下载结果；HEAD 成功不保证附件 GET 成功。无法复现或确认时，保留为待诊断原因。

配置依据：[pnpm 网络设置](https://pnpm.io/settings/network)、[Node 代理说明](https://nodejs.org/learn/http/enterprise-network-configuration)、[Git HTTP 代理](https://git-scm.com/docs/git-config#Documentation/git-config.txt-httpproxy)。

**本地包备用流程：** 直接安装因下载超时失败后，先按上述步骤排查；确需切换下载器时，可用 PowerShell 等保持证书校验的方式，从原始 Release 链接下载到当前实际 profile 下的持久缓存目录（如 `plugin-cache/`）。自行发起的请求设置 30 秒超时，最多尝试一次备用下载；仍失败则进入下方「暂停并等待用户提供 TGZ」，不连续更换脚本或镜像。

下载成功后，以 `deploy.json` 对应包的 `sha256` 校验文件；不一致立即停止。通过校验后用 `dsh plugin --profile <实际 profile> add "file:<TGZ 绝对路径>"` 安装，Windows 的 `file:` 路径使用正斜杠。仍须遵守版本检查，不能跳过宿主兼容性检查。若失败日志还在请求其他已安装的远程 TGZ，也检查对应依赖，按其实际版本处理，不能为了本地安装降级已安装的新版本。

`file:` 安装可能在依赖清单中保留本地绝对路径，因此保留缓存文件，并记录来源 URL、版本、摘要和实际路径；不要放入临时解压目录或安装后删除。除非网络恢复并成功验证，不自动改回远程 URL。缓存缺包时 `--offline` 不能代替下载。

给出链接后明确告诉用户：「自动下载未成功，我已暂停安装。请用浏览器下载上面列出的 `.tgz` 文件，不用解压，然后把文件拖进当前 DSH 对话发送给我。收到并校验通过后，我会从未完成的步骤继续。」不要让用户下载 Source code ZIP 来代替插件 TGZ。可选插件需要此方式时，只给出已核实的上游发行包链接，不编造下载地址。

### 二、引导用户配置聊天界面和人格

基础插件加载成功后，向用户介绍以下入口，并询问其偏好：

- **更换头像**：点击聊天头像可以换图；也可以在人设设置中给角色设置默认头像，手动设置的会话头像优先。
- **是否切分段落**：询问用户喜欢“一条完整回复”还是“像 QQ 一样分成多个气泡”。在「设置 → QQ聊天界面 → 对话分段 → 启用分段显示」调整，需要时再设置分段间隔。
- **设置人格**：提醒用户先到「设置 → 人设切换」添加角色，填写角色名称、性格、说话方式和背景；也可以从输入框下方「人设 → 添加人设」进入。
- **开始扮演**：提醒用户在对话前，从输入框下方的「人设」菜单选中想聊天的角色。设置了默认人设时，也应确认当前对话已采用该角色；未选中人设时沿用 DSH 原有设定。

「沉浸式 QQ」默认开启。用户找不到回复下方的复制、评价等按钮时，告知可在 QQ 设置中关闭。

### 三、需要表情包时

基础配置完成后，询问用户是否需要表情包。需要时安装并启用：

- 项目：[dsh-meme](https://github.com/yyh-001/dsh-meme)
- npm 安装目标：`dsh-meme@0.1.65`（安装反馈已验证的版本，无需本机 Git）。使用可用的插件管理器或 CLI 安装，仍检查插件兼容性。
- GitHub 源码备选：`github:yyh-001/dsh-meme`。需要本机 Git，且可能涉及构建脚本批准；不作为无 Git 环境的默认入口。

引导用户打开「设置 → 表情包」，安装或导入喜欢的图库，确认对应图库已启用，并按偏好调整主动发表情和发送方式。

之后可到人设设置中打开角色的「表情偏好」，选择优先图库、标签和发表情频率。提醒用户：角色偏好使用的图库仍需先在 dsh-meme 中安装并启用；频率通过提示词引导模型。

### 四、需要 AI 语音时

用户需要语音回复时，安装并启用：

- 项目：[dsh-fish-tts](https://github.com/MaRi23333/dsh-fish-tts)
- GitHub 安装目标：`github:MaRi23333/dsh-fish-tts`

此源码安装入口需要本机 Git，且可能需要批准构建脚本。没有 Git 时先说明此可选步骤的前置条件；无法满足时保留已完成的基础部署，暂不配置语音，不反复尝试同一安装目标。不要未经核实就换用同名 npm 包。

然后按顺序引导用户完成配置：

1. **注册账号**：打开 [Fish Audio 注册页](https://fish.audio/auth/signup/) 注册并登录。
2. **获取 API Key**：进入 [Fish 开发者控制台](https://fish.audio/app/developers/)，在 API Keys 中创建密钥，让用户自行填入 DSH「设置 → 语音朗读／Fish TTS」的连接设置并保存。
3. **寻找音色**：打开 [Fish 音色库](https://fish.audio/discovery/)，搜索、试听喜欢的声音，进入音色详情页，复制音色 ID（`reference_id`）。
4. **配置音色**：将 ID 填入 Fish TTS 设置的「音色 ID」，点击「应用音色」；按插件和账号可用项选择模型，再点击试听确认。
5. **绑定角色**：如希望不同角色使用不同声音，在「设置 → 人设切换」中点击对应角色的「绑定音色」，填写该角色的音色 ID，试听后保存。
6. **开启语音回复**：打开输入框下方的「语音／语音回复」开关，再到「设置 → QQ聊天界面」选择语音与文字的显示方式，以及自动生成或点击生成。

当前角色音色通过 Fish 的全局默认音色同步，多窗口同时使用时不保证音色隔离。遇到认证、额度或模型权限问题时，引导用户检查 Fish 控制台及插件错误提示。

### 五、完成部署

最后简要说明：

- 两个基础插件是否安装、启用，是否需要重启。
- 哪些其他 UI 美化插件已停用，是否仍有未排查的兼容问题。
- 用户选择的头像、分段方式和当前人格。
- 表情包、语音是否已配置，还有哪些步骤需要用户完成。

已有配置尽量保留；表情包和语音按用户需要添加。
